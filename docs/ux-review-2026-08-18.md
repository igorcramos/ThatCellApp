# UX review — 2026-08-18

## Scope and method

Review focused on mobile layout, shared-culture responsibility, and retroactive task completion. The in-app Browser connected successfully, but the local page did not finish rendering before the interaction timed out, so no reliable visual screenshot was available. Findings below combine the attempted browser check with structured inspection of the rendered markup, responsive CSS, interaction code, translations, and regression tests.

## Executive summary

The three requested capabilities are represented coherently in the integrated version:

- cultures expose a multi-select list of responsible people and save it through a dedicated database operation;
- the mobile breakpoint collapses major grids and cards to one column, wraps navigation, and removes page-level horizontal overflow;
- completing an off-schedule task now offers “On the scheduled date — I forgot to mark it” and records the event on the original planned date without deviation or schedule shift.

The largest remaining UX risk is scale: navigation and long checkbox lists become tall on a phone. The second is recovery from partial saves when the culture itself saves but its cell lines or responsible people fail to update.

## Prioritized findings

### P1 — Make long responsible-person lists searchable and summarize selections

**Evidence:** `#cultureMemberCheckboxes` renders inside the general `.checkbox-grid`. The responsive rule converts that grid to one column below 760 px. This prevents horizontal overflow, but a laboratory with many members produces a long form and pushes the save action far below the culture fields.

**Recommendation:** add a compact search field above the list, display a “N people selected” summary, keep currently selected people at the top, and consider a collapsed selector after selection. Preserve checkboxes because multiple responsibility is explicit and easy to understand.

**Acceptance check:** with 30 members at 390 px width, a user can find and add a second person without scrolling through the entire list; selected people remain visible before saving.

### P1 — Prevent or clearly recover from partially saved cultures

**Evidence:** culture save, cell-line links, and responsible-person synchronization occur in separate requests. Error messages explicitly say “Culture saved, but … could not be updated.” The form returns early, leaving the user to understand which parts persisted and retry safely.

**Recommendation:** preferably move culture, cell-line, and responsibility updates into one transactional database function. If that is not immediately feasible, keep the form in edit mode after a partial failure, highlight the failed section, and offer a focused “Retry responsible people” action.

**Acceptance check:** a simulated responsibility failure never leaves an ambiguous screen; the user can retry without creating a duplicate culture or losing entered selections.

### P2 — Reduce the vertical cost of mobile navigation

**Evidence:** at 760 px the navigation changes from horizontal scrolling to wrapped groups and wrapped tabs. This addresses the reported sideways movement, but all sections remain visible at once and can consume several rows before page content begins.

**Recommendation:** on mobile, show the active navigation group plus a compact “More sections” control, or use a group selector followed by only that group’s tabs. Avoid restoring page-level sideways scrolling.

**Acceptance check:** at 390 px, the application content begins within roughly the first screenful and every section remains reachable in two taps or fewer.

### P2 — Make retroactive completion wording and outcome unmistakable

**Evidence:** the dialog presents three radio-card choices and correctly hides the deviation reason for the original-date choice. However, “Today — keep schedule” is preselected, while the new forgotten-mark use case is the least destructive option and may be common for overdue items.

**Recommendation:** do not silently change the default without usage evidence. First, add a concise outcome line near the submit button that updates with the choice, for example “Activity date: 12 Aug · Schedule unchanged · No deviation.” Consider defaulting to the original date only if product policy confirms that this is the most common intended action.

**Acceptance check:** before submitting, the user can state which activity date will be stored and whether a deviation or schedule shift will be created.

### P2 — Improve the off-schedule dialog on short phone screens

**Evidence:** the dialog has three padded radio cards, conditional reason and notes fields, and actions in one scrollable modal. Its width and maximum height are responsive, but the heading and actions are not sticky.

**Recommendation:** use a sticky compact heading and sticky action footer on mobile; shorten secondary descriptions after a choice is selected. Ensure focus moves to the dialog title and returns to the triggering task after close.

**Acceptance check:** at 390 × 667 px, the selected outcome and “Complete task” action can be reached without losing context, and keyboard focus is restored to the task card.

### P2 — Replace generic responsible-person checkbox labels with identity-rich rows

**Evidence:** the shared-culture control is a generic checkbox grid. In labs with similar names, the choice may be ambiguous; responsibility is a permission-bearing action.

**Recommendation:** display full name plus email or lab role, visibly distinguish the culture creator/owner, and explain that selected people can view and update the culture. Disable removal of the creator if the backend always retains that person.

**Acceptance check:** users can distinguish two members with the same display name and understand the access granted before saving.

### P3 — Keep intentional scientific grids visibly scrollable

**Evidence:** plate and cryobox maps retain horizontal scrolling because their cell grids have fixed minimum sizes. Page-level overflow is clipped, which is appropriate, but users may not realize these specific regions can scroll.

**Recommendation:** add a subtle edge fade and a one-time “Swipe to see more wells” hint inside the map container. Keep scrolling local to the scientific grid, not the whole page.

**Acceptance check:** the page itself never moves sideways at 390 px, while all wells remain reachable inside the map.

### P3 — Validate compact controls against touch and text scaling

**Evidence:** most mobile controls receive a 44 px minimum target, including task actions. Some general compact and text buttons remain visually smaller, and long translated labels rely on wrapping.

**Recommendation:** test at 200% browser text zoom and with Portuguese labels. Keep icon-only controls at least 44 × 44 px and add accessible names/tooltips where the icon’s meaning is not obvious.

## Flow walkthroughs

### Create or edit a shared culture

1. Choose one or more cell lines.
2. Enter core culture and plate information.
3. Select multiple responsible people.
4. Save; the culture record, cell-line links, and responsibility links are updated.

The underlying flow supports the requirement. The recommended next iteration is a searchable identity-rich people selector plus transactional save/retry behavior.

### Complete a forgotten task on its correct date

1. Mark an overdue or early task complete.
2. In the off-schedule dialog, choose “On the scheduled date — I forgot to mark it.”
3. The deviation fields disappear and are no longer required.
4. Submit; the activity is stored with the planned date, with no deviation and no downstream schedule shift.

The implemented logic matches the requested behavior. The primary UX improvement is a live, plain-language outcome summary before submission.

## Recommended hands-on test matrix

- Desktop: 1440 × 900, English and Portuguese.
- Mobile: 390 × 844 and 360 × 800; also 390 × 667 for short screens.
- Text scaling: 200% zoom.
- Data scale: 0, 2, 10, and 30 responsible people; long names and duplicate display names.
- Failure states: culture save succeeds but membership update fails; retry succeeds.
- Task dates: late, early, today, month boundary, and daylight-saving boundary.
- Accessibility: keyboard-only dialog use, visible focus, screen-reader names, and focus restoration.

## Small changes applied during this review

No production change was applied. The browser did not yield a reliable rendered state, and the remaining improvements require product or interaction decisions; changing them based only on static inspection would add unnecessary risk.
